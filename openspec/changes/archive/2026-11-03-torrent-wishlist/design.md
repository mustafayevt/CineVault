## Context

A release search (`torrent_release_search`) builds a `TorrentQuery` from TMDB details and the library copy, runs every switched-on source into one merge (`cv_torrent::search`) and judges each release (`Assessment`: relevance, flags, pack, upgrade). The library side (`cv_app::torrents::library`) knows a movie's copies and a show's held and missing episodes without any lookup. Torrent search sits behind the responsibility notice; nothing is contacted before it is accepted.

## Decisions

- **Storage in the library database.** Two tables (migration 107): `torrent_wishlist` (one row per entry: kind, TMDB ID, title, year, poster address, scope, criteria as JSON, added, last checked, the last check's error, done, the episode a "next" entry looks for) and `torrent_wishlist_match` (one row per release found for an entry, keyed by the merge id, with its name, size, seeders, quality words, magnet, `.torrent` address, sources, when it was found and its state `new`, `seen`, `sent` or `dismissed`). Removing an entry removes its matches. These are no library rows: nothing here touches titles or media files.
- **One entry per title and scope.** Adding the same title and scope again replaces its criteria and clears done, so the Wishlist never holds two copies of one wish.
- **The check is the search, without the page.** For each entry: TMDB details → scope → the done rule → `build_query` → every source that applies, run with `cv_torrent::search::Orchestrator` into a collecting sink → the matching rows that pass the criteria. Entries are checked one after another (each already asks its sources at once), and one check runs at a time: a second request while one runs returns at once without checking.
- **Criteria on a release.** Relevance `Match` (the title and scope asked for), no flag at all, resolution at least the lowest chosen (an unknown resolution passes only Any), the source among those chosen (none chosen takes any; the words are the search's: `Remux`, `BluRay`, `WEB-DL`, `WEBRip`), HDR when asked for, the size at most the largest (an unknown size fails a set limit) and the seeders at least the fewest (unknown fails a set minimum).
- **Criteria on the library (done).** The same resolution, source and HDR rules on the copy the library holds; size and seeders do not apply. The library cannot tell a remux from an encode, so a Blu-ray copy meets "Remux". A movie is done when any copy with its TMDB ID meets them; a season when the library holds every aired episode the provider lists for it and the quality most of them share meets them; an episode when it is held and meets them. Done is stored, so a later change to the library does not undo it; editing the criteria clears it and judges again.
- **Next new episode.** From the show's aired episodes on TMDB (specials left out): the first one after the newest episode the library holds, or the newest aired one when the library holds none. When that episode has not aired yet the entry waits and says when it airs. When the episode looked for changes, the matches of the earlier one are dropped. Such an entry is never done.
- **When.** Each entry is due 6 hours after its last check. The UI asks for a due-only check once the app (or a browser tab) opens and every hour after; **Check now** checks every entry that is not done. Before the notice is accepted nothing is checked.
- **New and seen.** A match is `new` until the Wishlist is opened (`seen`). The sidebar count and the toast read the new matches; the toast appears when a check found new ones. Send marks a match `sent` (kept, dimmed); Dismiss marks it `dismissed`, hidden and never stored again for that entry.
- **The view.** `/torrents/wishlist`, reached by a "Search · Wishlist" segmented switch at the top of both Torrents views. Adding opens `/torrents/wishlist?add=movie:123` (with `season`, `episode` or `next=1` for a show), where the editor sits at the top of the list as part of the page; editing opens the same editor in place of the entry. Pickers are pages, so there is no dialog.
- **Defaults.** Lowest resolution 1080p. For a movie the library holds: one step above its best copy (720p → 1080p, 1080p → 2160p; a 2160p copy without HDR asks for HDR; a 2160p HDR copy asks for a Remux). A show opens on "Next new episode", or on the season or episode the search page had chosen.

## Risks

- A source that is down makes an entry look empty; the entry shows the check's failure when no source answered, and the next check tries again.
- Many entries take many requests: the 6-hour rule and one check at a time keep it light, and each source keeps its own limits.
- Safety: the feature writes no file in a media folder and never hands a release over by itself.
