# developer-tooling Specification

## Purpose
Covers what contributors use to build and check CineVault: the Rust and UI checks, the CI workflow, the generated IPC bindings, the compatibility fixtures and their runner, the tolerant NFO-reader samples, the pinned development copies of external tools, the screenshot and Movie-page layout checks, the performance budget suite, the third-party notices, opt-in live tests, and the workspace rule that denies `unsafe` code.

## Requirements

### Requirement: Rust checks
The Rust workspace (`crates/*`, `src-tauri`, `cli`, edition 2024) SHALL pass `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` (also available as the alias `cargo lint`) and `cargo test --workspace`. Test temporary files SHALL be kept inside the `target` folder (`TMP`, `TEMP` and `TMPDIR` point there through `.cargo/config.toml`).

#### Scenario: A clippy warning
- **WHEN** a change introduces a clippy warning
- **THEN** `cargo lint` fails

### Requirement: UI checks
Inside `ui/`, the frontend SHALL pass `bun run lint` (ESLint with no warnings allowed), `bun run typecheck` (`tsc --noEmit`), `bun run test` (Vitest), `bun run format:check` (Prettier) and `bun run build` (type check and Vite production build).

#### Scenario: Unformatted file
- **WHEN** a UI file is not formatted by Prettier
- **THEN** `bun run format:check` fails and names the file

### Requirement: CI workflow
`.github/workflows/ci.yml` SHALL run on pull requests to `main`, on pushes to `main` and by hand (`workflow_dispatch`), with one run per branch or pull request at a time (a newer push cancels the older run). It SHALL run on Windows and Ubuntu 22.04: the UI install and build, the Rust format, clippy and test checks, the compatibility fixtures, `node scripts/check-bundle.mjs`, the `release-publish`, `changelog` and version-file checks and `bun run site:changelog -- --check` on both (Ubuntu installs the WebKitGTK 4.1, GTK, D-Bus and OpenSSL development packages first), and the UI lint, typecheck, format and test checks and the OpenSpec specs validation on Ubuntu. On pushes to `main` it SHALL also build the installers of both systems and keep them as workflow artifacts for 7 days. macOS is not part of it until the macOS work of 1.2.0. It SHALL need only read access to the repository contents. The two build jobs (`Build and test (windows-latest)` and `Build and test (ubuntu-22.04)`) SHALL be required checks of `main`.

#### Scenario: Pull request
- **WHEN** a pull request to `main` is opened or updated
- **THEN** the checks run on Windows and Ubuntu and a failing check fails the run

#### Scenario: Push to main
- **WHEN** a commit is pushed to `main`
- **THEN** the checks run, then the Windows and Linux installers are built and kept as workflow artifacts for 7 days

### Requirement: Generated IPC bindings kept current
`ui/src/bindings.ts` SHALL be generated by `tauri-specta` from the Tauri commands and committed. A debug start of the app SHALL rewrite it, and `CINEVAULT_UPDATE_BINDINGS=1 cargo test -p cinevault-app` SHALL rewrite it too. The test `generated_bindings_are_up_to_date` SHALL fail when the committed file differs from what the commands generate.

#### Scenario: A command changes without new bindings
- **WHEN** a Tauri command gains a parameter and `ui/src/bindings.ts` is not regenerated
- **THEN** `generated_bindings_are_up_to_date` fails

### Requirement: Compatibility fixtures
`tests/compat/` SHALL hold committed fixture inputs (`fixtures/`) and expected outputs (`expected/`) for the Kodi, Jellyfin, Emby and MediaPortal formats: file classification, title, ID and stacking parsing, episode detection, NFO writing byte for byte, and rename destinations and file trees. The `cv-compat` crate (not shipped) SHALL run them, and `cargo test -p cv-compat` SHALL fail when any fixture fails.

#### Scenario: NFO output drifts
- **WHEN** a change alters one byte of a written movie NFO covered by a fixture
- **THEN** `cargo test -p cv-compat` fails for that case

### Requirement: Compatibility report and waivers
`cargo run -p cv-compat --bin compat-report -- --all` SHALL list each fixture as pass, fail, waived or pending, and `--require-complete` SHALL also fail on pending fixtures. Accepted deviations SHALL be listed in `tests/compat/waivers.json`, each with its family, case id, deviation code and reason. A waived case whose output matches SHALL fail the suite as a stale waiver.

#### Scenario: Stale waiver
- **WHEN** a waived case starts to match its expected output
- **THEN** the suite fails and says to remove the entry from `waivers.json`

### Requirement: NFO reader samples
`tests/nfo-read/` SHALL hold hand-written NFO files, some deliberately broken, with a `cases.json` describing what each should read as. The `cv-nfo` tests SHALL read them with the tolerant readers and check the results and which files count as NFOs CineVault can read.

#### Scenario: Broken nested episode NFO
- **WHEN** the reader tests run over `episode-broken-nested.nfo`
- **THEN** the readable episode data is recovered as `cases.json` describes

### Requirement: Pinned development tools
`bun run tools:fetch` SHALL download the pinned MediaInfo, FFmpeg and indexer service for the system it runs on (Windows, macOS or Linux x86_64) into the git-ignored `.dev-tools/` folder (or the folder in `CINEVAULT_TOOLS_DIR`), with the same manifest, size and SHA-256 checks as the app. It SHALL accept package names (`mediainfo`, `ffmpeg`, `indexer-service`), `--dir <folder>`, `--force` and `--help`. Media tests that need a tool SHALL use that folder and skip when the tool is missing. Downloaded binaries SHALL stay out of git.

#### Scenario: Fetch one tool
- **WHEN** `bun run tools:fetch -- ffmpeg` is run
- **THEN** only FFmpeg is downloaded into `.dev-tools/`, and a download whose checksum differs installs nothing

#### Scenario: Fetch on Linux
- **WHEN** `bun run tools:fetch` is run on Ubuntu x86_64
- **THEN** the `linux-x86_64` builds of MediaInfo, FFmpeg and the indexer service are in `.dev-tools/`

### Requirement: Screenshot check
`bun run shots` (in `ui/`) SHALL start the Vite dev server with the synthetic backend, or use one given with `--url`, open each route in headless Chrome with a throwaway profile, and capture it in dark and light at 1440×900 and 1366×768 into the git-ignored `ui/.shots/`. It SHALL fail on console errors, uncaught exceptions or horizontal overflow.

#### Scenario: Overflow found
- **WHEN** a route is wider than the window at 1366×768
- **THEN** `bun run shots` fails for that route and theme

### Requirement: Screenshot options
`bun run shots` SHALL accept `--routes`, `--all` (every route), `--themes`, `--sizes`, `--url`, `--out`, `--full` (the whole scrollable page), `--scroll`, `--steps` (clicks plus `focus:`, `key:` and `eval:` steps run after load), `--reduced` (reduced motion), `--scale` (device pixel ratio) and `--visible`, which fails when a listed element is not on screen without scrolling.

#### Scenario: Click before capture
- **WHEN** `bun run shots` is run with `--steps` naming the CSS selector of a button
- **THEN** the button is clicked after the page loads and the capture shows the result

### Requirement: Movie page layout check
`bun run check:facts` (in `ui/`) SHALL open the Movie page fixtures at 1366×768 and 1440×900 in both themes and fail when the plot (`.cv-plot`), the director and release facts (`[data-fact=director]`, `[data-fact=released]`) or the Technical summary rows (`[data-spec=video]`, `[data-spec=audio]`, `[data-spec=file]`) are not wholly visible when the page opens.

#### Scenario: Plot pushed below the fold
- **WHEN** a header change pushes the plot below the first screen at 1366×768
- **THEN** `bun run check:facts` fails

### Requirement: Performance budgets
`bun run perf:budgets` (from the repository root, after `bun run build` in `ui/`) SHALL run the budget probes in the release profile, one at a time, and exit non-zero when a budget fails; `--skip` SHALL leave out named probes. The probes SHALL generate their libraries in temporary folders and never touch the user's folders.

#### Scenario: Slow query
- **WHEN** a change makes the first page of a sorted query over 20,000 titles take 150 ms
- **THEN** the query probe fails and `bun run perf:budgets` exits non-zero

### Requirement: Budget limits
The budgets SHALL be: the first page of filtered, sorted and full-text queries over 20,000 titles under 100 ms; a rescan of an unchanged 5,000-movie library under 10 seconds; cold start under 1.5 seconds; input latency under load with p99 under 50 ms; and smooth scrolling of the poster grid (`bun run perf:grid`). `bun run perf:coldstart` SHALL time the real release window on a 5,000-movie portable install on Windows.

#### Scenario: Rescan budget
- **WHEN** the rescan probe runs over an unchanged 5,000-movie library
- **THEN** it passes only when the rescan ends within 10 seconds

### Requirement: Third-party notices
`bun run notices` SHALL regenerate `THIRD_PARTY_NOTICES.md` from the Rust dependency tree (with `cargo-about`) and the UI production dependencies.

#### Scenario: New dependency
- **WHEN** a Rust crate is added and `bun run notices` is run
- **THEN** its licence appears in `THIRD_PARTY_NOTICES.md`

### Requirement: Opt-in live tests
Tests that reach real services or a real library SHALL be opt-in through an environment variable and SHALL skip without it, so `cargo test --workspace` needs no network, keys or accounts. Examples: `CINEVAULT_LIVE_TOOLS=1` (the real MediaInfo download), `CINEVAULT_LIVE_NFO_AUDIT=1` (a read-only NFO audit of a copy of a real library) and the per-provider live tests. Keys SHALL never be written into code, tests, fixtures or the build.

#### Scenario: No credentials
- **WHEN** `cargo test --workspace` runs without any live variable set
- **THEN** the live tests skip and the run passes without network access

### Requirement: Unsafe code denied
The workspace SHALL deny `unsafe` code (`unsafe_code = "deny"`). The only exception SHALL be the MediaInfo FFI module in `cv-media` (`crates/cv-media/src/mediainfo/ffi.rs`), which SHALL use a scoped allow with a `SAFETY:` comment on every unsafe block.

#### Scenario: Unsafe block elsewhere
- **WHEN** a crate other than the MediaInfo FFI module adds an `unsafe` block
- **THEN** the build fails

### Requirement: Server checks
The Rust workspace checks SHALL cover the server crates as they cover the rest: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`. A parity test SHALL compare the desktop registry with the server dispatcher, matching command names and argument names, and SHALL fail when a command is missing from either side or an argument differs. HTTP tests SHALL cover sign-in, sessions, CSRF, the trusted proxy, image headers, media range requests, the folder browser's root jail, upload atomicity across volumes, the owner file and the secrets backend. A DOM test SHALL render the application shell in browser mode and fail when the shim's `metadata`, `transformCallback`, event or `convertFileSrc` contract changes. A Linux CI job SHALL build the container image, start it against a fixture data folder and run a scan, a rename and an artwork write before checking the health endpoint.

#### Scenario: A command only in the desktop app
- **WHEN** a contributor adds a command to the desktop app and not to the server
- **THEN** `cargo test --workspace` fails and names the missing command

#### Scenario: An argument renamed
- **WHEN** the server dispatcher expects `stop_jobs` and the desktop registry sends `stopJobs`
- **THEN** the parity test fails and names the command and both names

#### Scenario: The shim contract changes
- **WHEN** a Tauri update removes `metadata.currentWindow`
- **THEN** the shell render test fails before a browser sees a blank page

#### Scenario: Container smoke test
- **WHEN** CI builds the image and starts it on a fixture data folder
- **THEN** the scan, rename and artwork write succeed, `/healthz` answers 200, and the test fails otherwise

### Requirement: Server scripts
The repository SHALL offer `bun run server:dev` (build the UI and start the server against the developer's data folder), `bun run server:build` (the release server program), `bun run server:image` (build the container image), `bun run server:package` (the `.deb` and `.rpm`) and `bun run server:tarball`. `AGENTS.md` SHALL list them with the other commands, and `scripts/check-scripts.mjs` SHALL fail when a `bun run` command named in `AGENTS.md` or `README.md` does not exist in a `package.json`.

#### Scenario: Local server
- **WHEN** a contributor runs `bun run server:dev`
- **THEN** the interface is built and the server starts on the loopback address with the local data folder

#### Scenario: A command named in the docs does not exist
- **WHEN** a script is renamed and `AGENTS.md` still names the old one
- **THEN** `bun run check:scripts` fails and names the missing command

#### Scenario: Release artifacts
- **WHEN** a maintainer runs `bun run server:image`, `server:package` and `server:tarball`
- **THEN** the image, both packages and the tarball are produced and each reports the workspace version

### Requirement: Notices and version
The third-party notices SHALL be regenerated with `bun run notices` when the server adds dependencies (`axum`, `tower-http`, `argon2`, `chacha20poly1305` and the stream implementation), and the version check SHALL cover the image tag, the server package versions and the tarball name as well as the four project files.

#### Scenario: A new dependency without notices
- **WHEN** a server dependency is added and `bun run notices` is not run
- **THEN** the notices check fails and names the licence entry that is missing

#### Scenario: A version mismatch
- **WHEN** the image tag or a package version differs from the workspace version
- **THEN** `node scripts/check-version.mjs` fails and names the file or tag
